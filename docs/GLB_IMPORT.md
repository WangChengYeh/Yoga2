# 自備 GLB 學員：交件與匯入規格

這是外部製作模型的交件規格，不是三張照片重建成功的教學。可以自行製作，或交給 AI／3D 製作者。委託前先請對方提供符合下列骨架規格的測試檔，在 Yoga2 實際匯入與檢查動作後再定稿。檔案可以成功解析，不保證人物相似度、蒙皮品質或衣服不穿模。

## 在 Yoga2 使用

1. 開啟「匯入模型，使用自己的學員」→「匯入 GLB／三張圖設定」，勾選檔案使用權與本機處理。
2. 選「選擇 GLB 並預覽」。即使手機顯示原生檔案欄已清空，狀態文字仍會顯示讀入檔名與大小；同一檔案也能重新選取。
3. 骨架與檔案檢查通過後，右側會暫時換成你的模型。旋轉共用視角確認正面、側面、背面；開啟相機測試舉手、展臂、側傾。外觀保留模型原網格與貼圖，系統只正規化尺寸、位置與朝向來帶練。
4. 返回設定，按「本次套用」或「保存並套用」。保存至此網站的 IndexedDB，下次在同一瀏覽器自動讀入；儲存失敗可仍用本次套用。取消預覽會還原上一個學員。
5. 「準備 GLB 下載」可取回原上傳檔；「刪除並還原預設」會移除保存的 Avatar。換手機／瀏覽器需重新匯入，清除網站資料也會刪除模型。檔案不會自動傳到伺服器。

## 模型與貼圖

- 單一 GLB 2.0，最多 30 MiB；網格、骨架、貼圖全部內嵌，沒有外部 URL、外部檔案或 data URI。
- 最多 20 萬頂點、30 萬三角形、4096 個節點。手機建議更低，例如 3～6 萬三角形、單張 2048 貼圖。限制是匯入預算，不代表所有手機均可流暢運行。
- PNG／JPEG 貼圖，每張尺寸最多 4096×4096，最多 16 張、總計最多 32 Mi 像素；不使用 Draco／Meshopt／KTX2。
- 使用標準 PBR 材質。衣服、皮膚、頭髮要在模型本身完整；不要以相機朝向的平面冒充立體人體。可以包含多個蒙皮網格。
- 頭朝 +Y、臉朝 +Z，腳踩地，單位建議公尺。採用正確綁定的 A／T 參考姿勢、正值縮放，套用不必要的物件變換。系統統一到約 1.72 公尺作場景顯示，不代表真人身高。
- 靜態雕像不能作為動作學員；必須有骨架、inverse bind matrices、JOINTS_0／WEIGHTS_0，權重有效且總和約為 1。動作由相機骨架驅動，不播放檔案內原有動畫。

## Yoga2-Humanoid-1 骨架

需要下列 22 個關節，允許中間插入額外關節，但左右不可互換。髖部與脊椎、肩臂、腿腳必須有正確祖先關係。額外手指骨與臉部骨可保留，目前不會驅動。

| 部位 | 由上到下／由內到外的關節鏈 |
| --- | --- |
| 軀幹 | Hips → Spine → Spine1 → Spine2 → Neck → Head |
| 左臂 | Spine2 → LeftShoulder → LeftArm → LeftForeArm → LeftHand |
| 右臂 | Spine2 → RightShoulder → RightArm → RightForeArm → RightHand |
| 左腿 | Hips → LeftUpLeg → LeftLeg → LeftFoot → LeftToeBase |
| 右腿 | Hips → RightUpLeg → RightLeg → RightFoot → RightToeBase |

自動支援完整標準名稱與以標準名稱結尾的前綴（如 mixamorig:Hips）。不是所有 Mixamo 匯出都能直接使用，仍需具備完整 22 關節與階層。

其他命名可在「進階骨架對照」填寫 JSON，左邊是上表標準名稱，右邊是模型內實際名稱。例如：

```json
{"Hips":"pelvis","Spine":"spine_01","Spine1":"spine_02","Spine2":"spine_03"}
```

這只是部分示例；其他關節也若不同名，須一併填寫。對照會與 GLB 一起保存。對照只能解決命名差異，不能補造缺少的骨骼或修正錯誤蒙皮。

## 驗收

先測站姿、雙手上舉、展臂、側傾，再檢查三個視角。確認肩頸、腋下、髖膝沒有裂開，衣服不掉片、臉部不扭曲，雙腳不漂浮。上傳檢查成功只代表可載入及骨架結構符合；人物像不像照片與動作時的外觀品質，仍需以這些實際畫面驗收。
